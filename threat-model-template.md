# Product Threat Model Template

## 1. Product context
Intended use, deployment environment, lifecycle and security assumptions.

## 2. Assets
Identify safety/security-relevant data, identities, keys, firmware, configuration, services and audit evidence.

## 3. Architecture and trust boundaries
Document components, interfaces, data flows, privilege transitions and external dependencies.

## 4. Threat scenarios
For each scenario record: asset, entry point, preconditions, attacker capability, impact and affected lifecycle phase.

## 5. Risk treatment
Record security requirement, architectural control, implementation owner, verification method and residual risk decision.

## 6. Traceability
Maintain traceability from threat/risk to requirement, design decision, test evidence and released product version.
